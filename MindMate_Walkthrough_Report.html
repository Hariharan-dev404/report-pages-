MindMate: Full Architecture & System Walkthrough

A full-stack, algorithmic, and architectural deep dive into the offline-first AI mental wellness companion featuring Three.js 3D GLB humanoid avatars, local Ollama LLM streaming, TextBlob sentiment scoring, K-Means behavioral clustering, and crisis de-escalation protocols.

Framework: Django 6.0+ / Python 3.14 3D Runtime: Three.js WebGL (20 Ready-To-Use GLB Models) LLM: Local Ollama (Port 11434) ML Engine: Scikit-learn (K-Means) & TextBlob Status: 27/27 Tests Verified (100% Pass)

1. Executive Summary & Project Vision

MindMate is an emotionally intelligent, private-by-design digital companion built to support students, professionals, and young adults coping with stress, academic anxiety, isolation, and burnout. Unlike conventional wellness applications that outsource intimate emotional conversations to third-party cloud APIs (such as OpenAI or Anthropic), MindMate executes 100% of LLM reasoning locally on the host machine using Ollama, guaranteeing zero privacy leakage.

🎭 3D Humanoid Companion Engine

Full 20-character library (10 male, 10 female) of rigged GLTF/GLB models with real-time WebGL rendering, custom Three.js orbit lighting, procedural skeletal animation (idle, talking, listening, thinking), and zero-dependency SVG fallback.

⚡ Real-time Streaming LLM (Ollama)

Direct newline-delimited JSON (NDJSON) streaming over HTTP. Employs dynamic system prompt injection of companion persona and user memory embeddings, backed by conversational rule fallbacks.

📊 Dual-Tier Sentiment & Crisis Engine

Continuous TextBlob polarity evaluation alongside crisis keyword heuristics. Automatically detects multi-day negative mood streaks (4+ days) to trigger emergency de-escalation, localized hotlines, and safety alerts.

🧠 K-Means Behavioral Pattern Clustering

Unsupervised machine learning on 8 interaction dimensions (mean sentiment, ratios, volume, 7-day velocity) to classify non-diagnostic wellness trends and deliver tailored exercise recommendations.

5. Core Subsystems Deep Dive

5.1 The 3D Companion System & ReadyPlayerMe GLB Rig

20 Unique Humanoid Avatars: MindMate houses a comprehensive 3D asset library of 20 distinct ReadyPlayerMe characters (10 male, 10 female) stored in static/models/companions/. Each model has been cryptographically verified with unique SHA-256 signatures, validated skeletal structures, and dedicated WebP preview thumbnails.

  • Single Source of Truth: The system is driven by manifest.json. The API endpoint GET /api/character/library dynamically reads and parses this manifest, ensuring zero hardcoding discrepancies between frontend filters and filesystem assets.
  • Three.js Scene Graph & Rendering: Loaded inside static/js/character3d/ using THREE.GLTFLoader. The viewport is illuminated by a three-point lighting setup (soft ambient light, primary key directional light at (5, 10, 7), and an accent rim light (-5, 5, -5)) creating cinematic depth and realistic PBR materials.
  • Procedural Skeletal Animation: Built into character-animation.js. Rather than relying on bulky external animation tracks, the engine manipulates humanoid bone rotations (Spine, Neck, Head, Shoulders, Arms) using trigonometric sine waves and elapsed delta time:
    • idle: Subtle natural breathing expansion, gentle head sway, and ambient micro-movements.
    • listening: Attentive forward lean, subtle empathetic head nods.
    • thinking: Thoughtful upward head tilt and slight gaze displacement.
    • talking: Dynamic conversational head gesturing and expressive pacing synchronized with text generation.
    • happy / celebrate: Warm joyful wave and upright posture on positive milestones.
  • Graceful Degradation Hierarchy: If WebGL is unavailable or fails on mobile browsers, the system cascades seamlessly: 3D GLB Model → Procedural Three.js Humanoid Mesh → Dynamic SVG Vector Avatar.

5.2 Conversational AI & Streaming Architecture

  • Direct NDJSON Streaming: Unlike traditional REST endpoints that buffer the entire LLM output before returning, MindMate utilizes Django's StreamingHttpResponse. As tokens arrive from Ollama's /api/chat, they are immediately formatted as newline-delimited JSON chunks: 
    {"type": "chunk", "text": "I"}
{"type": "chunk", "text": " hear"}
{"type": "chunk", "text": " you, and that sounds really overwhelming."}
{"type": "end", "sentiment_score": -0.4, "mood_category": "Negative", "ai_name": "Luna"}
    This enables a fluid, typewriter-style conversational experience with instantaneous time-to-first-token.
  • Personality Persona Injection: The system prompt dynamically binds the user's chosen companion persona (Buddy, Listener, Coach, Motivator, Study Partner, Calm Friend), ensuring conversational tone, vocabulary, and empathy align with user expectations.
  • Semantic Vector Memory: Incoming messages are passed to get_embedding(). Cosine similarity evaluates past user statements against stored Embedding records (threshold < 0.99) to recall relevant past discussions without cluttering prompt tokens.
  • Dual-Layer Fallback Cascade: If Ollama is offline or encountering model loading delays, the system falls back to a high-speed, rule-based emotional fallback generator that delivers nuanced, persona-aligned replies within 15 milliseconds.

5.4 Wellness Intelligence & K-Means Unsupervised Clustering

To provide actionable insights beyond simple mood averages, MindMate incorporates an unsupervised machine learning pipeline in core/services/wellness_analysis.py:

Feature Name Data Source Mathematical Representation Behavioral Significance
avg_sentiment ChatHistory.sentiment_score ∑(scores) / N Overall emotional equilibrium across all sessions.
positive_pct mood_category == 'Positive' Positive Count / N × 100 Frequency of positive celebrations and resilience.
neutral_pct mood_category == 'Neutral' Neutral Count / N × 100 Reflective, task-oriented, or routine conversations.
negative_pct mood_category == 'Negative' Negative Count / N × 100 Proportion of interactions expressing distress or fatigue.
total_chats Count(ChatHistory) N Overall longitudinal engagement with the platform.
recent_frequency Chats in last 7 days Count(Chats where date ≥ now - 7d) Current activity surge or withdrawal velocity.
negative_ratio Negative / Total Negative Count / N Normalized vulnerability score.
positive_ratio Positive / Total Positive Count / N Normalized optimism score.

The Clustering Pipeline:

  1. Validation Gate: Requires a minimum threshold of 5 chat interactions before running clustering, preventing noise and overfitting.
  2. Feature Standardization: Employs Scikit-learn's StandardScaler to normalize varying feature scales (percentages vs raw counts) to zero mean and unit variance.
  3. K-Means Execution (k=3): Partitions the user's historical feature matrix into 3 distinct behavioral archetypes:
    • Positive Wellness Pattern: Characterized by high sentiment polarity (> 0.25) and low negative ratio. Recommends gratitude journaling and focus exercises.
    • Balanced / Mixed Pattern: Characterized by moderate sentiment with balanced emotional distribution. Recommends grounding and box breathing.
    • Higher Stress Pattern: Characterized by elevated negative ratio and increased chat velocity. Recommends 4-7-8 Relaxation and Sleep Wind-Down sessions.

5.5 Interactive Mindfulness & Wellness Exercise Engine

  • Catalog of Curated Activities: Features 6 clinically grounded mindfulness categories (Breathing, Stress Relief, Relaxation, Mindfulness, Focus, Sleep Wind-Down).
  • Dynamic Canvas Animation Engine: The detail view at /exercises/<id>/ dynamically renders CSS/JS breathing circles that visually expand during inhalation (4s), hold stationary during breath retention (7s), and smoothly contract during exhalation (8s), accompanied by audio prompts and phase instructions.
  • Streak Calculation Algorithm: Queries ExerciseCompletion ordered by date. Calculates consecutive active days and preserves records of milestone consistency.

7. Security, Privacy, and Constraints

  • Privacy by Architecture: Ollama runs locally on the host machine. User conversations and emotional expressions are processed locally without third-party LLM cloud API data leakage.
  • Strict Data Ownership: All custom character, chat history, and exercise APIs verify request.user.is_authenticated and scope database queries strictly to user=request.user.
  • Cascade Purging: Every associated table (CustomAICharacter, AI_Companion, ChatHistory, Embedding, MonthlyProgress, ExerciseCompletion) specifies on_delete=models.CASCADE. Account deletion irreversibly purges all records.
  • Zero Medical Claims: All system language and exercises are framed as general mental wellness, mindfulness, and breathing exercises. Official national helplines are provided whenever severe distress is detected.
